Pagination is broken three ways and none of them is visible. get.ts:68 ends with transactions.slice(offset, limit) — Array.slice takes (start, end), not (offset, count). Second, get.ts:62 sorts ascending, so page 0’s slice(0, 1000) is the oldest thousand; an account past 1000 transactions can never page to anything it has not already got. Third, hasMore never becomes false: History.tsx:87 tests allRestEntries.length === 0, but allRestEntries is mergeAndSort(restEntries, []), which is non‑empty as soon as anything has loaded, so the sentinel stays armed and refetches the same rows forever.
